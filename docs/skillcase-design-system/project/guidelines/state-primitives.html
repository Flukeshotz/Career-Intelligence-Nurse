The error block

Verbatim in ExamSelect, PaperSelect, ExamBlockSelector and DescribeSpeakSelect — same padding, same icon, same type scale, same underlined retry:

<div className="w-full text-center py-12 flex flex-col items-center gap-3">
  <AlertCircle className="w-6 h-6 text-red-500" />
  <p className="text-slate-500 text-xs font-semibold">Failed to load exams. Please try again.</p>
  <button className="text-[#002856] text-xs font-semibold underline underline-offset-2">Tap to retry</button>
</div>

Some failures ship the same block without the retry link — ExamCongratulations ("Failed to load final report."), ExamSpeakingResults, ExamReadingResults, ExamWritingResults. That is a meaningful product decision, not an omission: a results screen whose report failed has nothing useful to re-fetch, so the affordance is withheld rather than offered dead. The primitive therefore makes onRetry optional and renders no button without it.

The empty block

The same frame, one line, no icon: w-full text-center py-12 text-slate-400 text-xs font-semibold. Found in ExamSelect, PaperSelect, ReadListenTopicSelect, DescribeSpeakSelect, NotesListPage, VideoListPage, CourseSelectPage, NewsHome, AllEventsPage.

Critically, the copy is different every time and often branches: VideoListPage distinguishes "No matching videos." from "No videos in this course yet."; NotesListPage and ReadListenTopicSelect do the same. A search-empty state is not a nothing-here state, and the product already knows that. So the primitive takes message with no default — a generic fallback would quietly erase a distinction the product makes deliberately.

Why three families were left alone. The brief's instruction was the smallest primitives the evidence requires. The module-chapter skeleton has a different fill, border colour and row height because it mirrors a different row component; folding it into SkeletonList would mean adding a third variant that shares none of the first two's values — a component with three mutually exclusive appearances is a switch statement, not a primitive. The single-card and reader skeletons have two instances each, which is repetition but not yet a pattern. All three are recorded here so the next person does not mistake omission for oversight.

Disabled / locked — a divergence, not a primitive

Two different values ship for what looks like the same idea: chapter gating dims to 50% (ChapterSelectTemplate), a spent usage limit dims to 60% (ExamSelect). Both add cursor-not-allowed.

This pass corrected an error in our own documentation. ChapterRow's .d.ts previously asserted that chapter locks and usage locks "both render the same". They do not. That claim came from an earlier pass that read one file and generalised; the .d.ts now records the real divergence and flags it as probably accidental. No component was created — a 10% opacity difference between two features is a bug report, not a design-system primitive.

3Validate against Guided German

The required check: do these primitives serve the one fully-audited flow?

Honest answer: no, and they should not. This is a negative result worth recording rather than papering over.

Guided German stateProduction markupFits the primitive?
Lesson loading<div className="w-full lg-screen-height flex justify-center items-center">Loading Lesson...</div>No. Full-viewport centred text, no skeleton at all.
Lesson error / 409 unavailableThe same full-screen centred frame with the server's messageNo. Not a list surface; nothing to retry into.
Home hub journey loadingw-[200px] h-[210px] … bg-white/70 backdrop-blur-sm rounded-[20px]No. A journey-card placeholder with its own glassy treatment.
Disabled CTAs (quiz, unjumble)bg-neutral-200 text-neutral-400 cursor-not-allowedNo — and correctly so. LessonFooter already owns this, and it is a grey-out, not the blue busy pulse.

What the negative result tells us. The state primitives are list-surface primitives. Guided German is a linear task flow, and it handles its states differently on purpose — a lesson mid-flight has no list to skeleton and no fetch to retry. Forcing the new primitives into it would have been the generic-UI-kit failure mode the brief cautions against.

So the validation outcome is a scope correction, not a pass: these two primitives serve the ~11 remaining list-and-detail surfaces, and Guided German's own state gaps (documented in the flow audit) remain a separate job requiring LessonFooter and AudioTapButton changes instead.
