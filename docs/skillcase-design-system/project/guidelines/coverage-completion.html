Closing the coverage gap

Phase 5. The four surfaces the consolidation report named as unvalidated — Profile, Content, Scholarship and A1/A2 content — traced against the code. The readiness answer was ALMOST, and the boundary is the audit line. This moves the line. It also overturns two things phase 4 asserted.

0What the gap was hiding

1. The most reused composition in the product was invisible for four phases. One list row — w-full p-3 bg-white rounded-xl border border-zinc-200 flex gap-3 — carries exam select, paper select, describe-speak topics, read & listen topics and sources, video courses, video lists and notes. Ten-plus surfaces across six features. Every prior audit walked past it because within any one surface it reads as "that screen's list". It only became visible when Content was traced and the identical markup turned up in features with nothing else in common. Now extracted as ListRow.

2. Scholarship is not an exam variant — it is a proctored assessment system. Tab-switch detection, a three-strike violation counter that auto-closes the attempt, a server-authoritative timer polled by heartbeat, one attempt only, and results withheld until an administrator releases them. Nothing else in SkillCase does any of this. Phase 4 listed System C as "unknown" and guessed it was a funnel reusing the shell. That guess was wrong in kind, not just in detail.

3. Profile is not a profile. It is a 1,753-line screen with two tabs, and the second one calls jobScreeningApi — the job pipeline's document endpoints. Document upload, PDF preview and deletion live in both the pipeline and the account area against the same backend. UploadRow and DocumentReader are therefore cross-system components that the system had filed under Jobs.

4. "Content" is not a system. Video courses, news/read-listen, notes and short stories share a list row and a gate hook and nothing else — no shared model, no shared progress concept, no shared result. Phase 4 declined to promote Content for lack of evidence. The evidence now exists and it says the same thing: do not promote it.

1Scholarship — the system nobody had read

pages/scholarship/ is three files: ScholarshipHome, ScholarshipExamPage, ScholarshipResult. The behaviour in the middle one has no precedent anywhere else in the product.

Proctoring

Violation detection
visibilitychange on web (the comment notes native uses a different event, and that registering both would double-count). Leaving the exam screen fires triggerWarning("Left the exam screen", awayMs).
Strike model
Server-counted. recordWarning returns the authoritative warning_count; at 3 the client calls handleAutoSubmit("warnings") and the attempt closes with status auto_warnings.
Warning surface
A modal with three dots that fill red as strikes accrue, and the line "{3 − n} warning(s) remaining". Strikes survive a reload — the modal reappears on mount if warning_count > 0.
Timer
Server-authoritative. A local countdown for display, reconciled against getTimeRemaining; a expired flag in any response force-submits. This is materially stronger than the B1 exams' localStorage expiry timestamp.
Urgency
isUrgent = remainingSeconds < 300. The scholarship exam has the time-remaining feedback the B1 exams lack — the phase 3 report proposed it as a design gap; it already exists, five minutes out, in the system nobody had read.

States, and why they are new

not_started·in_progress·completed — results withheld·completed — released·warned_out·auto_closed·blocked

Four of those have no equivalent elsewhere. "Results awaited" is a completed assessment whose score exists and is deliberately not shown — the product's only instance of a withheld result. warned_out / auto_closed is a terminal failure state reached by conduct rather than performance, with an admin-contact hint and no retry. And the hub expresses all of them through the mascot — mayaWave, mayaSmiling, mayaThumbsup, mayaSad — which is the first evidence in the product of Maya carrying state rather than instruction.

Consequence for the system. The three-exam architecture (D-010) is confirmed and strengthened: System C shares primitives with A and B and nothing above them, exactly as recorded. But the reason is now known rather than assumed — it is a proctored, one-attempt, externally-released assessment, which is a different product from a practice paper. The Maya-as-state finding also reopens the mascot question (D-014) with new evidence: there are now four registers, not three.

2Profile — two products in one file

1,753 lines, two tabs, and a domain nobody had written down.

TabContainsSystem it belongs to
profileAvatar upload, personal details, qualification / experience / gender enums, plan card (Premium / Trial with days-left / Free), transactions link, logoutAccount + Payments

The qualification list — GNM Nursing, BSc Nursing, Post Basic BSc, MSc, ANM, Physiotherapist, Doctors, Pharmacists, Dentists — is the clearest statement of the product's actual audience found in any file so far. SkillCase is a German-language and placement product for Indian healthcare professionals. That was implicit in the job pipeline; here it is an enum.

Findings

  • Document handling is cross-system. UploadRow, DocumentReader and the upload/preview/delete triple serve both the pipeline and the account area against one API. Reclassified from Jobs-only to cross-system in the component map.
  • The plan card is a fourth entitlement surface. Premium / Trial-with-days-left / Free-with-upsell. It overlaps PlanSummaryCard and FeatureStatusChip without using either. Investigate
  • CustomSelect exists to avoid native OS dropdowns ("No OS native blue menus"). A deliberate product decision, and the system has no select component at all. Genuine gap
  • Icon imports are defensive — LucideIcons.FileCheck || LucideIcons.FileText || LucideIcons.File, repeated fifteen times. Evidence that the icon set is unstable, which is DS-3 with a concrete cost.

Content uses useUsageLimitGate("ALL", "video_courses"); the exams use useUsageLimitModule("B1", "exams"). Two hooks, two shapes, one concept. The system had seen only the second. Recorded as debt, not resolved

Phase 1 found the ten Select screens were one template forked in two. The content screens are the same story at larger scale: six module types — flashcard, grammar, listening, reading, speaking, test — mirrored file-for-file across both levels, with A1/A2 prefixes and shared hooks (useTextToSpeech from pronounce/).

A2TestResults.jsx is empty. Zero bytes. Someone began extracting the test-results screen from the A2 fork and stopped. A1 still renders its results inline at the foot of A1TestQuestions.jsx. This is the clearest single artefact of the fork being an accident rather than a decision — and it is a dead file in the repository. Recorded as a defect.

An eighth scoring rule also surfaces here: the A1/A2 test posts answers and reads back res.data?.passed — a server-computed boolean. The product does have a pass/fail concept; it lives on the server, for one module type, and no client screen states its threshold. That sharpens the open question rather than answering it.

7Revised readiness

Still ALMOST — but for a different reason

The audit line is now closed. Every product surface named in phase 4's unknown list has been traced, and the system covers them: the components exist or their absence is recorded, the states are mapped, the divergences are documented. Coverage is no longer what holds readiness back.

What holds it back is what phase 4 already scored lowest and this phase did not touch: accessibility is still undefined (2/10), and there is still one template (3/10), so screen production remains assembly rather than instantiation. Phase 5 raises coverage confidence; it does not raise those.

Maturity moves from 5.5 to 6.0 — components 7→8 (ListRow plus corrected classifications), cross-product consistency 4→5 (the divergences are now known rather than latent). Nothing else moved, because nothing else was worked on.

9Recommended next step

Unchanged from phase 4, and this phase reinforces it.

Wire the semantic token tier. ListRow made the case concrete: one composition repeated across six features, and every copy hard-codes #e4e4e7, #002856 and 12px independently. That is exactly the class of divergence a semantic tier prevents structurally rather than by discipline — and it is why the two hover treatments could diverge without anyone noticing.

The alternative worth naming: declare marketing and admin out of scope first. It is a five-minute decision that permanently bounds the system, and until it is made every future audit inherits an open-ended backlog.
