Coverage gaps

Three different things have been conflated in earlier reports: a surface being audited, its parts existing as components, and it having screens. This separates them, so "what's missing" has one answer. Updated after the phase-8 build: the exam gap and two of three template gaps are closed.

0The exam answer

The exam system has no screens, and that was deliberate — but stale. At phase 3 the instruction was explicit: "do not create exam screens yet. The output should be the behavioural map + reusable pattern extraction + validated scoring system." That was delivered — the three-system architecture (D-010), the scoring kit, and ExamTimerPill / BlockProgressTrack / DifficultyBadge as an Exam chrome components card.

The hold was never lifted, which left the largest audited surface in the product as the only one with no screens. Closed in phase 8: all eight screens now exist in ui_kits/exam-flow/ — four workspaces and four results — built against the new task template, and they established a fourth colour context in the process (D-030).

3What phase 8 built, and what is left

Phase 8 shipped: the task template, the select template, LiveRegion, TextField, and all eight exam screens. Building the template and its hardest instances together was the right call — the exam surface exercised timed sections, block progress, two scoring models and answer review, and forced the template to be honest about all four.

It also exposed a colour context the system had not separated: exam surfaces pair sky-950 headings with a blue-950 CTA, and Review Answers is navy one screen away from that CTA. Recorded as D-030. There are four contexts, not two.

  1. Lesson template — the last of the four. A retrofit: Guided German screens exist, so the template should reproduce them exactly rather than reinterpret them.
  2. Recap / daily goal / streak — three modals with real production sources, currently unbuilt. The smallest remaining screen gap.
  3. Screen-reader pass — the only thing keeping accessibility below 6, and the only gap that cannot be closed by reading code.
  4. The three AA colour corrections — measured, staged, awaiting one decision.

Still not in scope: scholarship, Profile and Content screens until their state machines are traced. Building from a route map rather than an implementation is how the wrong template gets baked in.

Honest summary

KNOWN: seven surfaces have screens and are audited to state level — the exam system included, as of phase 8. Foundations, 925 tokens, 96 components, the pattern layer and three of four templates are complete and traceable. Four colour contexts are explicit and tokenised.

KNOWN GAP: the lesson template (a retrofit), the recap/streak modals, and 26 recorded defects none of which have been actioned in the codebase.

UNKNOWN: screen-reader behaviour; the scholarship state machine; whether Profile and Content need anything the three templates do not already provide. The system can now generate new screens in every audited surface — which was the goal, and is a different claim from "the application is fully audited", which remains false.
